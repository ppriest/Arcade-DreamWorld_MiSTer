MAME 0.289, dreamwld.cpp. scripts/sprite_load.py: the drawn 4 KB of sprite RAM dumped
at every vblank start (the list screen_vblank copies), 1800 frames per run, same runs and
input stimulus as write_timing_mame.txt (attract --skip 600; play --coin 600 --skip 1500).
Counts are 16-pixel tile rows per visible line (224 lines a frame), geometry from
draw_sprites() including the wrap at 512.

  rows     every block whose Y span covers the line (no X test)
  visible  only tile columns overlapping X 0..307
  --blank  visible rows that are not all pen 0 after the spritelut redirect

Findings:
- Every set parks its unused entries on visible lines but off-screen in X: up to 512-514
  rows a line by Y alone. An engine must test X before fetching.
- With X tested, the worst real scene is 113 rows on a line (rolcrush/rolcrusha attract);
  p99.9 is 43-113 by set.
- cutefght clears the whole list to zero between scenes: 512 entries of tile 0 at X=-12,
  Y=0, all visible on lines 0-15. spritelut[0] in cutefght points at tile 0, which is
  blank: nothing is drawn.
- Non-blank visible rows: at most 64 on any line of any run; p99.9 27-46.
